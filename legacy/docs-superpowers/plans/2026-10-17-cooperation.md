# Dual-system cooperation

Implement the user's requested priority order within the existing general-purpose loop.

1. Bind approval to one pending operation, page fingerprint and goal revision. Show the action before approval; consume the approval once. Reject stale approvals and invalidate them on guidance or stop.
2. Pass System 2's actual stopping predicate to System 1 and verification. Keep the original user goal authoritative. Store bounded, timestamped page evidence across navigation; provide it to both systems without changing observed-target execution.
3. Ground verification and extracted rows in source IDs and exact quotes. Derive source URLs from observations, never model-authored URLs. Show concise public recovery summaries and source links in the console.
4. Run offline regression tests, browser checks and a bounded live multi-site research attempt. Report failures and measured call counts separately from hypotheses. Do not claim a successful flight workflow unless its final evidence proves it.

OpenRouter remains the configured System 2 provider; direct Anthropic stays selectable. No credentials, fixed destinations/dates, site-specific action plans, or private model reasoning in the UI.

- Real console + Chromium + configured Jev/OpenRouter models completed a two-source Python download/documentation comparison. Two browser actions, three policy decisions, three System 2 requests, two cited rows. Raw observations and quotes were checked against the result; the browser console reported no errors.
- Real flight attempts remain unsuccessful. Google Search presented an unusual-traffic challenge. Direct Flights navigation exercised origin/destination, one-way and date controls, but independent verification rejected the missing multi-source comparison. A subsequent attempt paused on malformed System 2 tool JSON. No booking or purchase was attempted.
- Approval buttons and source links were also checked in Chromium with an explicitly stubbed WebSocket; backend approval/recovery tests are offline. These checks are distinct from the real-model console run.
- Local raw records and measurement limits: `artifacts/cooperation-validation.json`. These are smoke observations, not latency/pricing/calibration benchmarks or recovery guarantees. Flight comparison is still an unmet demo target.
